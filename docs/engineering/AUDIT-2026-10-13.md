# Audit issue #4 dan #39, 13 Oktober 2026

Pembaruan rilis: kode audit ini telah dideploy pada 13 Oktober 2026 setelah migrasi produksi `0008` berhasil. Versi Worker `702c8835-88c8-490a-9872-317ae5f4eb0f`, commit kode `37a59ea`. Pemeriksaan HTTP produksi lulus; [log rilis](ENGINEERING.md) mencatat rinciannya. Keterangan "belum deploy" di bawah merupakan catatan saat audit lokal selesai; keterbatasan LCP dan uji pembaca layar tetap berlaku.

## Hasil dan batas pemeriksaan

- **#4: implementasi lokal selesai.** DNS yang cocok dan respons HTTP sukses saja tidak lagi membuktikan kepemilikan. Situs harus menyajikan token acak 256-bit milik klaim pada `/.well-known/tongkrongan-verification.txt`. Token berganti saat record diedit. Claim dan Dashboard menjelaskan cara memasangnya. Jalur tombol verifikasi dan Cron memakai fungsi yang sama.
- Hasil verifikasi yang terlambat hanya boleh menulis status bila token masih sama dan klaim belum ditangguhkan. Edit, klaim ulang, atau penangguhan selama request HTTP berjalan tidak boleh diloloskan oleh hasil lama. SQL aktivasi kedua jalur diuji langsung dengan SQLite bawaan Node; flag `--experimental-sqlite` mempertahankan dukungan Node 22.6.
- Migrasi lokal `0008_ownership_token.sql` berhasil. **Produksi belum dimigrasi atau dideploy.** Terapkan migrasi sebelum Worker baru. Klaim lama yang sudah aktif tidak otomatis dicabut; bukti token wajib ketika diverifikasi kembali. Termasuk alur integrasi Vercel: pengguna tetap perlu menerbitkan berkas bukti pada proyeknya.
- **#39: audit otomatis dan perbaikan temuan selesai; issue belum sepenuhnya selesai.** Lighthouse accessibility 100 pada lima halaman, 30 kombinasi halaman/tema serta dialog mobile tanpa pelanggaran axe pada aturan yang diuji. Target LCP 2,5 detik belum tercapai pada pengukuran akhir. VoiceOver/NVDA belum diuji langsung; hasil otomatis bukan pengganti pengujian pembaca layar.
- Dua notifikasi hasil dikirim ke webhook Discord sesuai instruksi pemilik, keduanya diterima dengan HTTP 204. Pesan kedua memuat pekerjaan #39 yang masih tersisa dan penjagaan hasil verifikasi lama pada #4.

## Temuan yang diperbaiki

| Temuan | Perbaikan |
| --- | --- |
| Judul animasi memberi `aria-label` pada span tanpa peran yang mendukung nama | Teks utuh khusus pembaca layar, potongan animasi disembunyikan dari accessibility tree |
| Tab demo beranda memakai opacity yang menurunkan kontras menjadi 2,5:1 | Hapus opacity dari teks tab |
| Placeholder papan alamat pada tema dark/ocean di bawah 3:1 | Gunakan token `board-dim` tanpa opacity tambahan |
| Papan alamat memakai peran `text` yang tidak standar | Peran `img` dengan nama alamat lengkap |
| Grup platform, tipe record, alasan laporan tidak mendukung tombol panah | Satu tab stop, Arrow/Home/End memindahkan fokus sekaligus memilih |
| Pemilih tema membaca `event.currentTarget` setelah callback event selesai | Simpan elemen grup sebelum `requestAnimationFrame` |
| Fokus dialog bisa kembali ke kolom awal setiap render; kontrol tersembunyi ikut hitungan fokus | Pakai `<dialog>.showModal()` untuk modalitas, fokus, Escape, dan pemulihan fokus native |
| Perubahan langkah klaim tidak memindahkan fokus ke konten baru | Fokus judul langkah setelah transisi masuk selesai |
| Nama aksesibel tombol tema/sandi tidak memuat teks yang terlihat | Sertakan `ID`/`EN`; ubah label sandi menjadi "Lihat kata sandi" |
| Footer muncul lalu bergeser ketika halaman lazy selesai dimuat | Cadangkan tinggi viewport pada main |
| Font utama baru diminta setelah CSS diproses | Preload berkas Latin Plus Jakarta Sans dari HTML |

Desain mengikuti `DESIGN.md`: layanan subdomain untuk pelajar, UMKM, kreator; papan nama dan stabilo; ENERGY 2 / RHYTHM 3 / MOTION 3. Tidak mengganti identitas, font, atau enam tema.

- Keyboard: fokus judul wizard; Arrow/End pada platform dan tipe; dialog mempertahankan fokus selama mengetik, Tab tidak mencapai konten di belakang, Escape memulihkan fokus pemicu; panah pemilih tema dan alasan laporan bekerja tanpa galat browser.
- Axe: WCAG 2 A/AA dan 2.1 AA, lima halaman pada light/dark/kopi/mint/grape/ocean, ditambah dialog 360 px. Fixture API pada skrip audit akhir membuat hasil dapat diulang tanpa mengubah akun atau DNS.

- **Belum dilakukan:** VoiceOver/NVDA, perangkat pembaca layar nyata, Firefox/Safari, Lighthouse sesi login di produksi, verifikasi DNS/HTTP ke hosting sungguhan, migrasi/deploy produksi.

## Menjalankan ulang

Alat audit opsional dipasang terpisah agar tidak mengubah dependensi aplikasi:

```sh
npm install --prefix /tmp/tongkrongan-audit --no-save playwright @axe-core/playwright lighthouse
npm run build
npm run db:local
npx wrangler dev --port 8787 --var DNS_MODE:mock --var DISCORD_WEBHOOK_URL: --var TURNSTILE_SITEKEY: --var REQUIRE_EMAIL_VERIFY:0 --var RESEND_API_KEY:
```

Di terminal lain, arahkan `AUDIT_CHROME` ke executable Chromium yang tersedia. Jangan menjalankan kedua audit bersamaan saat mengukur performa.

```sh
export AUDIT_NODE_MODULES=/tmp/tongkrongan-audit/node_modules
export AUDIT_CHROME=/path/to/chromium
node scripts/audit-accessibility.mjs
node scripts/audit-lighthouse.mjs
```

Skrip menolak host selain localhost/127.0.0.1. Audit aksesibilitas memakai fixture API; Lighthouse memakai API lokal. Tidak ada pengiriman webhook selama audit.
